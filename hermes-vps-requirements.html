What actually matters for a Hermes box

Self-hosted agent stacks are not like a simple WordPress blog. They stay resident (a gateway holds an in-memory session + tool runtime), they do bursts of CPU work during thinking/compaction, and they hold RAM for the session history. The three things that matter most:

ResourceWhy it mattersRough floor (estimate)
CPU coresagent reasoning, compaction, concurrent tool calls2 vCPU comfortable; 1 vCPU is workable for a single user
RAMsession history, Node runtime, Docker (n8n), caching2 GB minimum for Hermes + n8n; 4 GB comfortable
DiskSSD-backed for compactions + Docker imagesNVMe strongly preferred over spinning disk

These are engineering estimates from how agent runtimes behave, not measured benchmark claims. Verified results will be added below as providers get tested for $0.

How we measure (the harness)

We measure with a portable, zero-cost, reproducible script set. The same harness runs on any Linux box — it needs no paid account and no special agent. The probes:

01 · System facts — OS, arch, CPU model + cores, total RAM, disk availability, virtualization. An oversold 1-core box will not hold a live agent gateway, and this shows it.
02 · CPU & memory probe — single-thread CPU loop plus memory write/read bandwidth. This reflects agent thinking and compaction load.
03 · Hermes-stack probe — Docker, Node, Python availability and container count. Most self-host stacks (Hermes, n8n, Kuma) run in containers.
